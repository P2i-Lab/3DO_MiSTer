# Interpretation
# - ioi_Offset counts from 00:00:00: block 17000 is sector 16850 of the image (CRC 9D2F38E8 checked on the image).
# - D13D1017 = device "CD", severe, ER_ParamError (23): the console rejects 2352 bytes on a data track, the core accepts.
# - SUBQ: 87 = command, 14 = ADR 1 + data track, track 1, index 1, absolute then relative position (binary), E3 = status.
#   Requested block 19000; the console is at 19002 (04:0D:1B), the core at 19001.
#   Differences with the core: byte 1 (80 / 00), byte 2 (14 / 41, nibbles swapped), status (E3 / E1, double-speed bit).
#   These core bytes come from our commit 2a9f1a9; they had no hardware reference.

# Model (hypothesis) of forward jumps, burned disc, towards block 5000
# T = 6688 us per block at 2X, 13376 us at 1X; R = one revolution = 68,3 ms at 2X, 136,6 ms at 1X (10,2 blocks).
# Time = (gap + 1) x T + n x R, n integer, the smallest result greater than or equal to a latency L.
# L between 26,75 and 33,4 ms at 2X, between 40,1 and 53,5 ms at 1X.
# Reproduces 14 of the 15 values within 0,2 %, gap 64 within 1 % (the revolution gets longer with the radius).
# Re-reading the same block (gap -1, version 2.3: 67,9 ms) follows the same rule.
# The SAUT (jump) lines of version 2.3 alternate forward jump and backward jump: they do not test this rule.
